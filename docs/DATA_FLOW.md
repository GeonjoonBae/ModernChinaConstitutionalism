# 데이터 흐름

## 1. 기사 수집과 통합

상하이도서관 『申報』 데이터베이스에서 `立憲`, `憲政`, `憲法`, `制憲`을 검색하여 네 검색 결과를 수집했다. 중복 기사는 `article_id`를 기준으로 통합하였다. 수집과 기사 단위 전처리의 코드·필드 구조는 [shlib-shenbao-dataset-workflow](https://github.com/GeonjoonBae/shlib-shenbao-dataset-workflow)에 공개되어 있다.

## 2. 분석 문맥 생성

기사의 `analysis_text`에서 각 핵심어 2글자와 좌우 50글자를 합한 102자 범위를 기본 문맥으로 추출했다. 한 기사 안에서 여러 문맥 범위가 실제로 중첩되는 경우에는 중복 집계를 피하기 위해 병합하였다. 이 과정에서 38,294개 문맥을 생성했다.

## 3. NLP와 토큰 프로필

CKIP `bert-base-chinese`로 단어 분절, 품사 태깅, 개체명 인식을 시행했다. 이후 다음 규칙을 단계적으로 적용했다.

1. 정규식 병합과 이체자 통일
2. 필수 exact 병합
3. 선택 exact 병합
4. 불용어 제거

`regex-only`는 1단계, `strict`는 1-2단계, `full`은 1-3단계까지 적용한 토큰 프로필이다. 실제 규칙은 `config/dictionaries/`에 제공한다.

## 4. 制憲 필터

1912년까지 `制憲`을 중심으로 생성된 문맥은 총독을 가리키는 별칭 용례로 확인되었다. 이 중 독립 토큰 `立憲` 또는 `憲政`이 함께 있는 context 9499, 10143, 10904는 문맥을 유지하되 총독 별칭에 해당하는 `制憲` 토큰만 마스킹했다. 나머지 초기 문맥과 1912년 이후의 예외 context 26955, 32404는 제외했다. 최종 분석 모집단은 36,923개 문맥이다.

## 5. 시기 구분

네 핵심어의 일별 출현량과 30일 이동평균, 핵심어 간 추종 양상의 변화, PELT 변화점 후보 및 역사적 해석 가능성을 함께 검토해 `long_period_manual`의 여섯 시기를 설정했다.

## 6. 공기어 네트워크

각 토큰을 노드로, 설정 window 안에서 함께 출현한 토큰 쌍을 edge로 구성했다. edge의 `joint_count`는 두 토큰이 같은 window 안에서 연결된 횟수다. 공개 edge 파일은 논문에서 직접 사용한 조건으로 제한한다.

## 7. 핵심어 쌍 유사도

각 핵심어의 상위 주변어 집합과 정규화된 edge 가중치를 이용해 Jaccard와 weighted Jaccard를 계산했다. 전체 시기는 window 1, 5, 10, 20, 시기별 비교는 window 10을 사용했다.

`multi_core_ego_network_dashboard.html`은 같은 집계 네트워크에서 핵심어별 상위 100개 주변어와 dominant POS를 결합하여 탐색형 자아망으로 표현한다. 공개판은 노드·에지·POS 집계만 포함하며, 로컬 분석판에서 제공한 에지별 원문 문맥은 제외한다.

## 8. Pair-conditioned keyness

두 핵심어 모두의 상위 100개 주변어에 포함되는 공유 주변어를 후보로 삼고, 두 핵심어와의 연결 횟수 중 작은 값인 `min`을 pair count로 사용했다. 같은 시기의 나머지 핵심어 쌍과 대비하여 다섯 keyness 지표를 계산한 후, 네 지표 이상에서 상위 30위 안에 드는 후보를 선별했다.

## 9. 정성적 검토

계산 결과는 의미를 자동 판정하는 결과가 아니라 정밀 독해가 필요한 문맥을 찾는 탐색 지표로 사용했다. 논문에서 직접 인용한 기사의 식별 정보는 `data/evidence/paper_context_index.csv`에 제공한다.
